# Plan — Pi context, compaction, ETA, and delegate fence assessment

**Owning Task:** T-167
**Approved:** operator asked-and-answered alignment exchange, 2026-07-27, this session.

## Intended outcome

Produce decision-grade evidence and explicit recommendations for pi-context-view, pi-blackhole and other state-of-the-art drop-in Pi compaction approaches, pi-eta, ZeroBoot, Gondolin, and Microsandbox against qq's current Pi and Landstrip operating model. Refine the ETA event boundary around the next expected point of operator interaction and reconcile that transition with the concurrent voice-design Change.

## Ownership boundary

The accountable session retains scope, source verification, recommendation judgment, durable report authorship, and delivery. One fresh read-only researcher performs the bounded investigation from a complete brief. The voice-design session contributes its independently developed operator-interaction transition semantics; it does not own this Task's conclusions.

## Method

1. Coordinate with the voice-design session on the shared transition concept and preserve any disagreement explicitly.
2. Give one fresh researcher the exact question, decision, current qq paths and threat model, candidate sources, comparison dimensions, and required confidence/citation shape.
3. Require primary-source and source-code inspection. Use isolated temporary probes only where they materially distinguish compatibility or claims; do not mutate the live Pi install or host confinement.
4. Spot-check every load-bearing source and claim. Separate observed facts, inference, and gaps.
5. Write exactly one confidence-tagged Backlog research report attached to T-167 with adopt / isolated-trial / hold / reject recommendations, dependencies, and smallest follow-up Checks.
6. Run Repository Checks appropriate to Backlog-only changes, obtain fresh-context review, and deliver one GitHub Flow pull request for operator merge.

## Non-goals

- Installing any candidate into the live Pi runtime.
- Replacing Landstrip or changing delegate permissions.
- Encoding an ETA rule into qq.
- Claiming “infinite context” or VM-grade isolation without evidence.
- Broad Pi package update assessment unrelated to these candidates.

## Observable success

- T-167's four acceptance criteria are met in one attached report.
- The ETA trigger and close are defined in observable operator-interaction terms and cover research, approved Change execution through PR, scope change, parallel work, and post-merge observation.
- Compaction recommendations distinguish automatic context quality from raw-history retention/retrieval and identify behavioral, accuracy, cost, privacy, and operational tradeoffs.
- Fence recommendations compare actual guarantees—not product labels—against qq's declared Landstrip threat model and workflow constraints.
- Fresh Checks and fresh-context review find no unsupported recommendation or Task/report inconsistency.

## Consequential decisions and dispositions

- One integrated research Task/report, with no adoption or host mutation: operator-approved exchange, 2026-07-27.
- ETA's working unit is the interval ending at the next expected operator interaction; “operator-ready handoff” is not settled vocabulary and must be reconciled with voice design: operator clarification in the same exchange.
- Compaction scope includes the state of the art in automatic drop-in improvement over Pi native compaction, not pi-blackhole alone: operator clarification in the same exchange.
- Follow-up adoption and migration decisions remain open and require separate alignment after this evidence.
