## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Outcome: `/update` becomes an operator-owned decision workflow rather than an autonomous assessment-to-PR pipeline. Before asking for any disposition it presents a complete decision card that explains the installed/owned state, candidate, concrete qq gain, deletable state, compatibility and operating cost, evidence confidence and gaps, safe test/rollback, and recommendation. It then reviews candidates with the operator one at a time, records only explicit dispositions, and fails closed before approval/finalization surfaces.

Decision ledger:
- Asked-and-answered operator exchange, 2026-07-27: “make this change to update so we get the behavior that you just described. Then we're gonna go through all of the candidates together, one at a time. For each you present the relevant information and we make a decision.”
- Same exchange: “Make sure you don't pollute your context by doing anything long running directly ... Delegate anything that is long running here to the appropriate actors.”
- The referenced behavior is the nine-field decision card stated immediately before approval: installed identity/owner; candidate identity; concrete gain; deletable state; compatibility/operating cost; confidence/unknowns; safe test/rollback; recommendation; explicit operator disposition. The same exchange explicitly approved making this prompt change now.
- Approved plan doc-108 captures the agreed outcome, boundary, implementation sequence, Checks, and success evidence.
- Decision-13 remains the boundary authority: invoking `/update` authorizes only governance-required evidence lifecycle, never a candidate disposition, recommendation implementation, or merge.

Non-goals: do not disposition or implement any ecosystem candidate in this Change; do not alter PR #254 or its assessment evidence; do not redesign general grilling/delivery governance; do not add an update engine, package mutation, browser/provider/auth flow, or merge automation.

## Acceptance Criteria
<!-- AC:BEGIN -->
- [ ] #1 Every inventoried component receives an operator-readable benefit/cost presentation; every meaningful-delta candidate gets the full nine-field decision card before any disposition is requested.
- [ ] #2 Candidates are reviewed one at a time; the workflow never batches disposition questions, interprets silence/placeholders as decisions, or advances until the operator explicitly disposes or defers the current candidate.
- [ ] #3 The prompt distinguishes evidence-lifecycle authorization from decision approval and stops before calling a plan approved, marking the Task Done, or presenting a ready-for-merge PR unless the required explicit operator approvals/dispositions exist.
- [ ] #4 Long-running inventory, research, verification, and review are delegated to appropriate fresh actors while the accountable operator-facing owner retains alignment questions, dispositions, and synthesis.
- [ ] #5 The existing complete inventory, primary-evidence, recommendation vocabulary, non-mutation boundary, rollback analysis, and never-merge requirements remain intact.
- [ ] #6 Focused regression checks prove the decision-card schema, sequential stop gates, explicit-disposition rules, delegation requirement, and absence of the old autonomous handoff path.
<!-- AC:END -->

## Definition of Done

- [ ] #2 One green pull request is handed to the operator; the agent does not merge it.

## Implementation Plan
