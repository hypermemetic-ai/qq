Outcome: move qq's global runtime line from Node 22.22.3 to exact Node 24.18.0 LTS, repair the browser stack with `pi-agent-browser-native@0.2.72` plus `agent-browser@0.33.0`, and replace the unused floating `pi-landstrip` carrier with exact direct `@landstrip/landstrip-linux-x64@0.17.31`. Update shared live/runtime and qq's reproducible patched-Pi build identity together only after isolated compatibility proof; the Landstrip enforcement version and policy remain unchanged.

Decision ledger:
- Asked-and-answered operator disposition, 2026-07-27: “update to twenty four for sure, but we're not doing it now ... make that its own task.” This records `update` for Node 24.18.0 and explicitly defers implementation to this separate Task/Change.
- Same exchange: “If anything else can reasonably be bundled with it, we'll bundle it with that same task.” Bundling is allowed only for a candidate that receives its own explicit operator disposition and shares the Node 24 qualification, promotion, and rollback closure.
- The Node candidate card established the selected target and rationale: Node 24.18.0 is LTS, includes the current security line, and satisfies `agent-browser@0.33.0`'s Node >=24 requirement, avoiding a second browser-only Node runtime.
- Asked-and-answered operator disposition on the browser candidate, 2026-07-27: `Update and bundle (Recommended)`. This records `update` for `pi-agent-browser-native@0.2.72` plus `agent-browser@0.33.0` and bundles that exact pair because it shares Node 24's test/promotion/rollback closure.
- Browser bundling does not transfer its credential/profile boundary: qualification starts with a fresh credential-free profile and independently proves doctor, artifacts, downloads/HAR/a11y, failure behavior, and process/profile teardown before promotion.
- Asked-and-answered operator disposition on the carrier candidate, 2026-07-27: `Replace and bundle (Recommended)`. This records `replace` for root `pi-landstrip: ^0.17.31` with exact direct `@landstrip/landstrip-linux-x64@0.17.31`. It shares T-166.1's snapshotted Node/npm package-tree migration, but remains a distinct acceptance unit; binary version, policy bytes, and enforcement semantics must not move.
- Implementation still requires its own explicit plan approval. A failed qualification stops; it does not silently fall back to Node 22.23.1, select another browser/Landstrip version, touch a real credentialed profile, or broaden into unrelated package/architecture migrations.

Non-goals until separately dispositioned and attached: do not update Pi core, pi-subagents, or unrelated packages merely because they can execute on Node 24; do not upgrade Landstrip beyond 0.17.31; do not remove Node 22 or current browser/carrier rollback state before acceptance; do not implement from the assessment Change.
